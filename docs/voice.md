# TripStudio Voice Charter v1

> 用户面前的所有文字都遵循这份章程。它不是风格偏好，是规则。
> 修改前先读《concept.md》，理解为什么这样克制。

---

## 第 0 条：底层叙事不上 UI

底层叙事见 `concept.md`（"两个你之间的信件往来"）。
那是产品**为什么这样设计**的解释，不是给用户看的话术。
UI 文字一律避免角色化。

## 第 1 条：第一/第二人称都不出现

不要：
- "我帮你保存了 5 个事件"
- "你已经添加了 5 个事件"
- "为你导入"

要：
- "已保存 · 5 个"
- "已添加 5 个事件"
- "导入完成 · 5 个事件"

例外：极少数已成习语的固定短语（"我的 Trip"作 panel 标题），单独评审。

## 第 2 条：状态优先于动作

不要："正在保存…"
要：  "保存中…"  /  "已自动保存"

## 第 3 条：术语与量词

| 概念 | 名词 | 量词 | 用在哪 |
|------|------|------|--------|
| Trip | `Trip`（不译） | — | 全局 |
| Event（数据维度） | `事件` | `个` | 默认。所有数量、动作、状态摘要 |
| Event（视觉维度） | `事件卡片` / `卡片` | `张` | 仅 onboarding 与卡片视觉的引导文 |

死规则：
- 量词`张`不能裸用——出现`张`就必须带`卡片`。"5 张" ❌、"5 张事件卡片" ✅
- 数据动作一律用`个`+`事件`："添加事件" ✅、"5 个事件" ✅、"3 个缺地点" ✅（上下文已明可省略`事件`）
- 默认场景下，能省名词就省："共 5 个" ✅（前后文已明确指代事件）

样例对照：

| 场景 | ✅ |
|------|----|
| 状态摘要 | `共 5 个 · 3 个缺地点` |
| 添加按钮 | `+ 添加事件` |
| 删除 confirm | `确认删除这个事件？` |
| 导入 toast | `导入完成 · 5 个事件` |
| Onboarding 视觉引导 | `从一张事件卡片开始` |

## 第 4 条：语气小词归零

砍掉：吧 / 哦 / 啦 / 呢 / 嗯 / 呀 / 呗
砍掉：感叹号（错误提示也不用）
砍掉：颜文字、波浪号

## 第 5 条：错误提示——指出位置，不评价

不要："导入失败！请检查文件格式。"
要：  "导入失败：JSON 顶层不是对象"

## 第 6 条：空态——陈述事实 + 一个动作入口

不要："这里还空空的，快来添加吧～"
要：  "还没有 Trip" + 一个 [新建] 按钮

## 第 7 条：隐喻只活在视觉，不活在文字

视觉层：卡片纸感、邮戳质感、地名章
文字层：始终是检索性标签（"事件"、"地点"、"日期"）

不要在文字里写"行程卡"、"小手帐"、"明信片"等隐喻词，除非它就是一个真实功能的名字。

## 第 8 条：长度优先短，不能短就直白

- 按钮：≤ 6 字优先
- toast：≤ 1 行
- confirm：陈述要做什么 + 提醒不可撤销（如有）

## 速查违例样例

| ❌ | ✅ |
|----|----|
| 你确认要删除吗？ | 确认删除？此操作不可撤销。 |
| 帮你导入了 5 条事件 | 导入完成 · 5 个事件 |
| 还没有作品哦～ | 还没有 Trip |
| 看个示例行程 | 加载示例 |
| 给这场旅行起个名字… | Trip 名称 |
| 5 张 | 5 个事件（裸用 5 个仅在上下文明确时） |
| 添加一张 | + 添加事件 |
| 删除这张事件 | 删除这个事件 |
| 从一张事件开始 | 从一张事件卡片开始（视觉引导） |
| 正在保存… | 保存中… |
