# TripStudio Concept Memo

> 内部产品备忘。**不暴露给 UI 文案**——所有用户可见文字遵循 voice.md 的"匿名陈述"规则。
> 这份文档存在的意义：解释 Phase 4 明信片为什么是核心，而不是导出选项。

---

## 三身位结构

```
       规划的你         探路的你          抵达的你
    ┌──────────┐    ┌──────────┐    ┌──────────┐
    │ 写下卡片 │ →  │ 替你出发 │ →  │ 用脚印体 │
    │  立意    │    │ 寄回感受 │    │   会     │
    └──────────┘    └──────────┘    └──────────┘
       现在            将来            最终

           ↑ 卡是去程的信       ↑ 明信片是回程的信
```

TripStudio 不是一个"行程规划工具"。它是**两个自己之间的信件往来**：

- **规划的你** —— 现在坐在屏幕前，写下要去的地方。
- **探路的你** —— 替你先走一遍，把感受、提示、种草寄回来（Phase 4 明信片）。
- **抵达的你** —— 将来某一天，用脚走过这一程。

事件**卡**是去程的信，明信片是回程的信。这就是为什么 v0.1 一开始就强调卡片感、为什么 Phase 4 要做明信片——它们不是装饰，是这个叙事的物理载体。

---

## 这层叙事如何影响设计

### 视觉层（可以体现）

- 卡片有纸的厚度感、阴影、圆角
- 明信片有邮戳、地名章、票据般的质感
- 时间感（"更新于 X 分钟前"）保留——信件是流的

### 文字层（绝不体现）

- 不出现"你"、"我"、"我们"
- 不出现"另一个你"、"探路"、"寄回"等隐喻词
- 不把工具拟人化（"我帮你..."）
- 不让用户感到产品在"对他说话"

用户拿到的是冷静的、匿名的、检索性的文字。卡片和明信片自己说话，工具闭嘴。

### Phase 4 明信片

明信片不是"导出 PNG"。它是这套叙事的**回程**：

- 触发入口的文案仍然中性（"生成明信片"、"导出明信片"），不写"让 X 替你寄回来"
- 但明信片本体的设计、布局、文字风格，要让人**感觉**它是从某个地方寄来的——日期戳、目的地章、笔迹般的字体
- 如果 Phase 5+ 接入 LLM/agent 写"探路感受"，那部分内容是**第二个角色的笔迹**，不是产品的解说词

---

## 设计决策的可追溯依据

| 决策 | 依据 |
|------|------|
| 事件以"卡"为视觉单位 | 去程的信 |
| 明信片是 Phase 4 唯一的输出形态 | 回程的信 |
| 卡片可拖拽、可分组、可标记完成度 | 信件可整理 |
| 不引入"发布"概念 | 信件是私人的，不是公告 |
| 不做 dashboard / 数据统计 | 不是工具的事 |
| 文案匿名化 | 用户更喜欢匿名性，不需要被产品"招呼" |

---

## 不会做的事

- 不会让产品**自我介绍**（如"欢迎使用 TripStudio"）
- 不会用 emoji 当语气词
- 不会写"小贴士"、"温馨提示"
- 不会做用户引导动画（onboarding 是一段静态可读的文字）
